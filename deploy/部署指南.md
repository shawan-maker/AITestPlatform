## 1. 环境要求

### 方式一（Nginx 手动部署）需要的组件

| 组件 | 最低版本 | 说明 |
|------|---------|------|
| Python | 3.10+ | 推荐 3.11 |
| Node.js | 18+ | 前端构建 |
| MySQL | 8.0+ | 数据库 |
| Redis | 6+ | Token 黑名单（可选） |
| Nginx | 1.20+ | 反向代理 + 静态文件 |
| RAG Server | - | 知识库服务（独立部署） |

### 方式二（Docker Compose 部署）需要的组件

| 组件 | 最低版本 | 说明 |
|------|---------|------|
| Docker | 20.10+ | 容器引擎 |
| Docker Compose | 2.0+ | 多容器编排（compose plugin） |
| Git | 任意 | 获取代码 |

> Docker Compose 方式下，Python/Node/MySQL/Redis/Nginx 全部运行在容器内，宿主机无需安装。

## 3. 方式一: Nginx 手动部署

### 3.1 后端部署

```bash
# 1. 克隆代码
cd /opt
git clone <repo-url> aitestplatform
cd aitestplatform

# 2. 创建虚拟环境
python3.11 -m venv venv
source venv/bin/activate

# 3. 安装依赖
pip install -r requirements-service.txt

# 4. 配置环境变量
cp .env.example .env
vim .env
# 必须修改的配置:
#   DATABASE_URL       - MySQL 连接地址
#   REDIS_URL          - Redis 连接地址（可选）
#   JWT_SECRET_KEY     - 替换为随机字符串！
#   RAG_SERVER_URL     - RAG 服务地址
#   BACKEND_HOST       - 保持 127.0.0.1（仅 Nginx 可达）
#   CORS_ORIGINS       - 留空（同域部署无需 CORS）
#   LOG_FILE           - logs/backend.log

# 5. 初始化数据库（全新部署）
python deploy/scripts/init_deploy.py
# 或从旧实例迁移数据：
# 1. 在旧服务器: python deploy/scripts/export_data.py --output backup.sql
# 2. 拷贝 backup.sql 到新服务器
# 3. python deploy/scripts/init_deploy.py
# 4. python deploy/scripts/import_data.py --input backup.sql

# 6. 启动后端（推荐使用 systemd 管理）
python main.py
# 或使用 uvicorn 直接启动:
uvicorn main:app --host 127.0.0.1 --port 8000 --workers 4
```

### 3.2 前端构建

```bash
cd frontend

# 安装依赖
npm install

# 构建生产版本（自动读取 .env.production）
npm run build

# 构建产物在 frontend/dist/ 目录
ls dist/
# index.html  assets/  ...
```

### 3.3 Nginx 配置

```bash
# 1. 复制 Nginx 配置
sudo cp deploy/nginx.conf /etc/nginx/conf.d/aitestplatform.conf

# 2. 编辑配置（修改关键项）
sudo vim /etc/nginx/conf.d/aitestplatform.conf

# 必须修改:
#   server_name  → 实际域名（如 test.example.com）
#   root         → 前端 dist 目录的绝对路径（如 /opt/aitestplatform/frontend/dist）

# 3. 测试配置
sudo nginx -t

# 4. 重载 Nginx
sudo nginx -s reload
```

### 3.4 Systemd 服务管理（推荐）

创建后端服务文件 `/etc/systemd/system/aitestplatform.service`:

```ini
[Unit]
Description=AITestPlatform Backend
After=network.target mysql.service

[Service]
Type=simple
User=www-data
WorkingDirectory=/opt/aitestplatform
Environment=PATH=/opt/aitestplatform/venv/bin:/usr/bin
ExecStart=/opt/aitestplatform/venv/bin/uvicorn main:app --host 127.0.0.1 --port 8000 --workers 4
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
# 启用并启动服务
sudo systemctl daemon-reload
sudo systemctl enable aitestplatform
sudo systemctl start aitestplatform

# 查看状态
sudo systemctl status aitestplatform

# 查看日志
sudo journalctl -u aitestplatform -f
```

## 4. 方式二: Docker Compose 全家桶部署（CentOS 7 从零部署）

> 推荐方式。MySQL + Redis + 后端 + 前端全部容器化，宿主机只需安装 Docker。
> 以下以 **CentOS 7** 为例，从空白服务器到前端页面可正常访问（含数据）。

### 4.0 环境清理（如服务器已安装过原生服务）

> 如果服务器是新装的空白系统，**跳过本节**，直接到 4.1。
> 如果之前已经在服务器上直接安装过 MySQL、Redis、Nginx 等服务，需要先停掉并清理，避免端口冲突。

#### 4.0.1 检查端口占用

```bash
# 检查关键端口是否被占用
ss -tlnp | grep -E ':3306|:6379|:80|:8000'
# 如果有输出，说明对应端口被占用，需要清理
```

#### 4.0.2 停止并卸载原生 MySQL

```bash
# 查看 MySQL 服务名（可能是 mysqld 或 mariadb）
systemctl list-units --type=service | grep -i mysql
systemctl list-units --type=service | grep -i maria

# 停止服务
sudo systemctl stop mysqld 2>/dev/null
sudo systemctl stop mariadb 2>/dev/null
sudo systemctl disable mysqld 2>/dev/null
sudo systemctl disable mariadb 2>/dev/null

# 卸载（保留数据目录以防万一需要备份）
sudo yum remove -y mysql-server mysql-community-server mariadb-server 2>/dev/null

# 确认端口已释放
ss -tlnp | grep :3306
# 应无输出
```

#### 4.0.3 停止并卸载原生 Redis

```bash
# 停止服务
sudo systemctl stop redis 2>/dev/null
sudo systemctl disable redis 2>/dev/null

# 卸载
sudo yum remove -y redis 2>/dev/null

# 确认端口已释放
ss -tlnp | grep :6379
# 应无输出
```

#### 4.0.4 停止并卸载原生 Nginx

```bash
# 停止服务
sudo systemctl stop nginx 2>/dev/null
sudo systemctl disable nginx 2>/dev/null

# 卸载
sudo yum remove -y nginx 2>/dev/null

# 确认端口已释放
ss -tlnp | grep ':80\b'
# 应无输出
```

#### 4.0.5 清理残留进程

```bash
# 检查是否还有相关进程残留
ps aux | grep -E 'mysql|redis|nginx|uvicorn' | grep -v grep

# 如有残留进程，强制终止（谨慎操作）
# sudo kill -9 <PID>
```

#### 4.0.6 确认环境干净

```bash
# 最终检查：关键端口应全部空闲
ss -tlnp | grep -E ':3306|:6379|:80|:8000'
# 无任何输出 = 环境干净，可以继续 Docker 部署
```

### 4.1 安装前置依赖

#### 4.1.1 安装 Git

```bash
# 检查是否已安装
git --version

# 安装（如未安装）
sudo yum install -y git
```

#### 4.1.2 安装 Docker

CentOS 7 官方 yum 源中的 Docker 版本过旧，需使用 Docker 官方源：

```bash
# 1. 卸载旧版本（如有）
sudo yum remove -y docker docker-client docker-client-latest \
    docker-common docker-latest docker-latest-logrotate \
    docker-logrotate docker-engine 2>/dev/null

# 2. 安装依赖工具
sudo yum install -y yum-utils device-mapper-persistent-data lvm2

# 3. 添加 Docker 官方 yum 源
#    国内服务器推荐使用阿里云镜像源（速度快）：
sudo yum-config-manager --add-repo https://mirrors.aliyun.com/docker-ce/linux/centos/docker-ce.repo
#    海外服务器使用官方源：
#    sudo yum-config-manager --add-repo https://download.docker.com/linux/centos/docker-ce.repo

# 4. 安装 Docker Engine + CLI + containerd + Compose 插件
sudo yum install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin

# 5. 启动 Docker 并设置开机自启
sudo systemctl start docker
sudo systemctl enable docker

# 6. 验证安装
docker --version          # 需要 20.10+
docker compose version    # 需要 2.0+（注意是 "docker compose" 不是 "docker-compose"）
```

> **非 root 用户运行 Docker（可选）：**
> ```bash
> sudo usermod -aG docker $USER
> # 需要重新登录 shell 才能生效
> ```

#### 4.1.3 配置 Docker 镜像加速（国内服务器推荐）

国内服务器拉取 Docker Hub 镜像可能较慢甚至超时，配置镜像加速器：

```bash
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json << 'EOF'
{
  "registry-mirrors": [
    "https://hub.rat.dev",
    "https://docker.rainbond.cc",
    "https://docker.1panel.live"
  ]
}
EOF

# 重启 Docker 使配置生效
sudo systemctl daemon-reload
sudo systemctl restart docker
```

> **⚠️ 镜像源不稳定怎么办：**
> 国内镜像源经常变动，如果上述源失效，可搜索"docker 镜像加速 2026"获取最新可用源。
> 备选方案：
> - 配置 Docker 代理（需科学上网）：编辑 `/etc/systemd/system/docker.service.d/http-proxy.conf`
> - 使用 `docker save/load` 离线传输（在有网络的机器上拉取后传到服务器）
>
> **推荐分步拉取镜像**（比 `docker compose up --build` 一起拉更稳定）：
> ```bash
> # 先单独拉基础镜像（小 → 大，逐个确认能连通）
> docker pull redis:7-alpine       # ~30MB，最快
> docker pull mysql:8.0            # ~500MB
> docker pull python:3.11-slim     # ~150MB
> docker pull node:18-alpine       # ~180MB
> docker pull nginx:alpine         # ~40MB
>
> # 全部拉完后再构建启动
> docker compose -f deploy/docker-compose.yml up -d --build
> ```
> 这样即使某个镜像拉取失败，已拉取的不会丢失，也不会互相阻塞。

### 4.3 配置环境变量

```bash
# 使用 Docker 专用模板
# 注意：.env 文件必须放在项目根目录（docker-compose.yml 通过 ../.env 引用它）
cp deploy/.env.docker .env
vim .env
```

> **⚠️ 重要：** `.env` 文件必须放在**项目根目录**（如 `/opt/AITestPlatform/.env`），不是 `deploy/` 目录下。
> `docker-compose.yml` 中的 `env_file: ../.env` 是相对于 `deploy/` 目录的路径。
> `DATABASE_URL` 和 `REDIS_URL` 无需在此文件中配置，它们由 `docker-compose.yml` 的 `environment` 字段自动构建。

**必须修改的配置项：**

| 变量 | 说明 | 示例 |
|------|------|------|
| `MYSQL_ROOT_PASSWORD` | MySQL root 密码，改为你自己的强密码 | `MyStr0ngP@ss2026` |
| `HTTP_PORT` | 前端 HTTP 端口（如 80 被占用则改） | `80` 或 `8080` |
| `LLM_BINDING_API_KEY` | 大模型 API Key | `sk-xxxx` |
| `EMBEDDING_BINDING_API_KEY` | 向量模型 API Key | `sk-xxxx` |
| `JWT_SECRET_KEY` | JWT 签名密钥（必须随机生成） | 见下方命令 |
| `RAG_SERVER_URL` | RAG 知识库服务地址 | `http://10.0.0.5:9621` |

```bash
# 生成安全的 JWT_SECRET_KEY
# 方式 1: 使用 openssl（CentOS 7 自带）
openssl rand -hex 32

# 方式 2: 使用 python3（如已安装）
python3 -c "import secrets; print(secrets.token_hex(32))"
```

> **注意：** Docker Compose 部署时，`DATABASE_URL` 和 `REDIS_URL` 由 `docker-compose.yml` 自动构建（使用容器内部网络地址 `mysql:3306` 和 `redis:6379`），无需在 `.env` 中手动指定。

### 4.5 构建与启动

```bash
# 【推荐】先单独拉取基础镜像（国内服务器网络不稳定时更可靠）
# 已在 4.1.3 中拉取过的可跳过此步
docker pull redis:7-alpine
docker pull mysql:8.0

# 构建并启动所有服务（MySQL + Redis + Backend + Frontend）
# 首次构建会拉取基础镜像 + 安装依赖，耗时约 5-15 分钟
docker compose -f deploy/docker-compose.yml up -d --build

# 查看启动状态（等待所有容器变为 healthy）
docker compose -f deploy/docker-compose.yml ps
# 预期输出 4 个容器，状态均为 running/healthy:
#   aitestplatform-mysql      running (healthy)
#   aitestplatform-redis      running (healthy)
#   aitestplatform-backend    running (healthy)
#   aitestplatform-frontend   running

# 查看启动日志（首次启动建议观察，确认无报错）
docker compose -f deploy/docker-compose.yml logs -f
# Ctrl+C 退出日志查看（服务继续运行）
```

> **构建失败排查：**
> - `npm ci` 失败 → 网络问题，检查 Docker 镜像加速配置
> - `pip install` 失败 → 在 `deploy/Dockerfile.backend` 的 `pip install` 后添加 `-i https://pypi.tuna.tsinghua.edu.cn/simple`
> - `apt-get` 失败 → Debian 官方源不可达，在 Dockerfile.backend 头部添加阿里云 Debian 源
> - 镜像拉取超时（Pulling 卡住 1h+）→ 参考 4.1.3 的分步拉取策略，先 Ctrl+C 取消，单独 `docker pull` 每个镜像
> - Ctrl+C 取消后已下载的层**会自动缓存**，重新执行会断点续传

### 4.6 初始化数据库

根据部署场景选择 **4.6A（全新部署）** 或 **4.6B（从旧实例迁移数据）**。

#### 4.6A 全新部署（空库）

```bash
# 等待 MySQL 健康（首次启动约 30 秒）
docker compose -f deploy/docker-compose.yml ps | grep mysql
# 确认 mysql 状态为 healthy

# 在容器内执行数据库初始化
# 注意：init_deploy.py 使用 asyncmy 驱动连接 MySQL（非 mysql CLI），
#       不受 MySQL 8.0 TLS 证书验证问题影响
docker exec -it aitestplatform-backend python deploy/scripts/init_deploy.py

# 该脚本自动完成：
#   1. 检查 .env 配置
#   2. 连接 MySQL（使用 asyncmy，兼容 Docker 容器内 MySQL 8.0）
#   3. 创建数据库 aiTestPlatform（如不存在）
#   4. Aerich init-db + upgrade（创建全部表）
#      如 aerich upgrade 超时，自动回退到 Tortoise.generate_schemas(safe=True)
#   5. 验证表结构
```

> **如果 backend 容器一直在重启循环中（无法 exec 进入）：**
> ```bash
> # 先停止 backend，用临时容器执行初始化
> docker stop aitestplatform-backend
> docker run --rm \
>   --network deploy_app-network \
>   --env-file deploy/.env.docker \
>   -v $(pwd):/app -w /app \
>   deploy-backend \
>   python deploy/scripts/init_deploy.py
>
> # 初始化完成后启动 backend
> docker compose -f deploy/docker-compose.yml up -d backend
> ```

初始化完成后，重启后端容器以触发默认管理员创建：

```bash
docker compose -f deploy/docker-compose.yml restart backend

# 等待约 30 秒（healthcheck 需要时间）
sleep 30

# 验证后端已启动且 healthy
docker compose -f deploy/docker-compose.yml ps | grep backend
# 预期: aitestplatform-backend   Up (healthy)

# 通过 Nginx 代理验证登录 API（OAuth2 表单格式）
curl -s http://127.0.0.1/api/v1/auth/login -d "username=admin&password=123456"
# 预期返回包含 "access_token" 和 "code": 200

# 默认管理员账号已自动创建: admin / 123456
```

#### 4.6B 从旧实例迁移数据

```bash
# ===== 在旧服务器（开发机）导出数据 =====
cd D:/PyProject/AITestPlatform
# 如果已有备份文件可跳过此步
PYTHONPATH=. python deploy/scripts/export_data.py --output deploy/backup_20260712.json

# 将备份文件传输到新服务器
scp deploy/backup_*.json user@server:/opt/aitestplatform/

# ===== 在新服务器操作 =====

# 1. 先初始化空库（建表）
docker exec -it aitestplatform-backend python deploy/scripts/init_deploy.py

# 2. 将备份文件复制到后端容器内
docker cp backup_20260712.json aitestplatform-backend:/app/deploy/

# 3. 执行数据导入（自动按 FK 依赖顺序导入 42 张表，跳过冲突记录）
docker exec -it aitestplatform-backend \
    python deploy/scripts/import_data.py \
    --input deploy/backup_20260712.json \
    --on-conflict=skip

# 4. 或使用一键迁移脚本（含自动验证，自动对比源库/目标库行数）
docker exec -it aitestplatform-backend \
    python deploy/scripts/migrate_to_server.py \
    --backup deploy/backup_20260712.json
```

### 4.7 验证部署

```bash
# 1. 检查所有容器状态
docker compose -f deploy/docker-compose.yml ps
# 4 个容器均应显示 running，backend 和 mysql/redis 显示 healthy

# 2. 检查后端健康接口（通过 Nginx 代理，端口 80）
curl -s http://127.0.0.1/health
# 预期返回: {"code":200,"message":"success","data":{"status":"ok"}}

# 3. 验证登录 API（OAuth2 表单格式）
curl -s http://127.0.0.1/api/v1/auth/login -d "username=admin&password=123456"
# 预期返回包含 access_token 和 "code": 200

# 4. 检查数据库数据（迁移场景，验证数据已导入）
docker exec -it aitestplatform-backend python -c "
import sys; sys.path.insert(0, '/app')
import asyncio
from tortoise import Tortoise
from service.core.settings import TORTOISE_ORM
async def check():
    await Tortoise.init(config=TORTOISE_ORM)
    conn = Tortoise.get_connection('default')
    for table in ['user', 'project', 'api_test_case', 'functional_case']:
        _, rows = await conn.execute_query(f'SELECT COUNT(*) as cnt FROM {table}')
        print(f'  {table}: {rows[0][\"cnt\"]} rows')
    await Tortoise.close_connections()
asyncio.run(check())
"

# 5. 通过浏览器访问
#    http://服务器IP          （HTTP_PORT=80 时）
#    http://服务器IP:8080     （HTTP_PORT=8080 时）
#
# 6. 登录
```

## 5. 数据库部署与迁移

### 5.1 场景说明

| 场景 | 命令 |
|------|------|
| **全新部署**（空库） | `python deploy/scripts/init_deploy.py` |
| **从旧实例迁移数据** | 旧库导出 → 新库导入 |
| **仅升级 schema**（数据不动） | `python deploy/scripts/db_manage.py upgrade` |

### 5.2 全新部署

```bash
# 1. 检查配置（不执行）
python deploy/scripts/init_deploy.py --dry-run

# 2. 执行初始化（建库 → 建表 → 应用迁移 → 验证）
python deploy/scripts/init_deploy.py

# 3. 启动后端（自动创建默认管理员 admin/123456）
python main.py
```

`init_deploy.py` 会自动完成：
- 检查 `.env` 配置是否完整
- 连接 MySQL 并创建数据库（如不存在）
- 运行 Aerich init-db + upgrade（创建全部 38 张表）
- 验证表结构

### 5.3 从旧实例迁移数据

#### 方案 A: mysqldump（推荐，最快速完整）

```bash
# === 旧服务器 ===
python deploy/scripts/export_data.py --output backup_20260708.sql

# 仅导出表结构（不含数据）：
# python deploy/scripts/export_data.py --output schema_only.sql --no-data

# === 传输到新服务器 ===
scp backup_20260708.sql user@newserver:/opt/aitestplatform/

# === 新服务器 ===
# 先初始化空库
python deploy/scripts/init_deploy.py
# 再导入数据
python deploy/scripts/import_data.py --input backup_20260708.sql
```

#### 方案 B: JSON 格式（跨数据库兼容，无需 mysqldump）

```bash
# === 旧服务器 ===
python deploy/scripts/export_data.py --output backup.json

# === 新服务器 ===
python deploy/scripts/init_deploy.py
python deploy/scripts/import_data.py --input backup.json --on-conflict=skip
```

JSON 导入的冲突处理策略：
- `--on-conflict=skip` — 跳过已存在的记录（默认）
- `--on-conflict=update` — 覆盖更新已存在的记录
- `--on-conflict=error` — 遇到冲突立即报错

## 7. 常见问题排查

### Q1: 刷新页面 404
**原因**: Vue Router History 模式需要 Nginx 回退到 `index.html`
**解决**: 确认 Nginx 配置中有 `try_files $uri $uri/ /index.html;`

### Q2: AI 智能体生成无响应 / 卡住
**原因**: Nginx 缓冲了 SSE 流式响应
**解决**: 确认 `/api/v1/ai-generation/` 的 location 块中有 `proxy_buffering off;`

### Q3: API 请求 CORS 报错
**原因**: 同域部署不需要 CORS，但后端仍配置了 CORS origins
**解决**: `.env` 中 `CORS_ORIGINS` 留空即可

### Q4: SSE 连接超时断开
**原因**: Nginx 的 `proxy_read_timeout` 太短
**解决**: 确保设为 700s 以上（大于 Agent 超时 600s）

### Q5: 文件上传失败 (413)
**原因**: Nginx 默认 `client_max_body_size` 为 1MB
**解决**: 在 Nginx 配置中设置 `client_max_body_size 20m;`

### Q6: 后端启动报 JWT 密钥警告
**原因**: 使用了默认的 `change-me-in-production`
**解决**: 在 `.env` 中设置安全的 `JWT_SECRET_KEY`（建议 32 位随机字符串）

### Q7: 健康检查失败
**排查**:
```bash
# 直接请求后端
curl http://127.0.0.1:8000/health

# 通过 Nginx/Docker 请求
curl http://your-domain.com/health

# Docker 部署：检查后端容器日志
docker logs aitestplatform-backend --tail 50
```

### Q8: Docker 构建时 pip/npm 超时
**原因**: 国内服务器访问境外源慢
**解决**:
```bash
# pip: 在 deploy/Dockerfile.backend 的 pip install 后追加:
RUN pip install --no-cache-dir -i https://pypi.tuna.tsinghua.edu.cn/simple -r requirements-service.txt

# npm: 在 deploy/Dockerfile.frontend 的 npm ci 前添加:
RUN npm config set registry https://registry.npmmirror.com
```

### Q9: Docker 容器启动后 backend 反复重启
**排查**:
```bash
# 查看容器退出原因
docker inspect aitestplatform-backend --format='{{.State.ExitCode}} {{.State.Error}}'

# 查看容器日志（含启动报错）
docker logs aitestplatform-backend --tail 100

# 常见原因：
# - DATABASE_URL 连接失败 → 检查 MySQL 容器是否 healthy
# - 缺少必需的环境变量 → 检查 .env 是否完整
```

### Q10: Docker 启动失败，端口被占用
**原因**: 服务器上之前安装过原生 MySQL/Redis/Nginx，端口 3306/6379/80 被占用
**解决**: 参考 [4.0 环境清理](#40-环境清理如服务器已安装过原生服务)，停掉并卸载原生服务后重新启动 Docker
```bash
# 快速查看哪个进程占用了端口
ss -tlnp | grep :3306
sudo lsof -i :3306
```

### Q11: Docker 镜像拉取超时 / 长时间卡在 Pulling

**原因**: 国内服务器访问 Docker Hub 被限制，镜像加速器不稳定或已失效
**排查**:
```bash
# 查看当前镜像源配置
cat /etc/docker/daemon.json

# 测试网络连通性
curl -v https://registry-1.docker.io/v2/ 2>&1 | head -20
```
**解决**:
1. **更换镜像源**（参考 4.1.3，尝试最新可用的源）
2. **分步拉取**（比一起拉更稳定，避免互相阻塞）：
```bash
docker pull redis:7-alpine     # 小镜像先拉，验证连通性
docker pull mysql:8.0
docker pull python:3.11-slim
docker pull node:18-alpine
docker pull nginx:alpine
```
3. **配置 Docker 代理**（如有科学上网条件）：
```bash
sudo mkdir -p /etc/systemd/system/docker.service.d
sudo tee /etc/systemd/system/docker.service.d/http-proxy.conf << 'EOF'
[Service]
Environment="HTTP_PROXY=http://代理IP:端口"
Environment="HTTPS_PROXY=http://代理IP:端口"
EOF
sudo systemctl daemon-reload
sudo systemctl restart docker
```
4. **离线传输**（在有网络的机器上拉取后导出）：
```bash
# 在有网络的机器上
docker pull mysql:8.0
docker save mysql:8.0 -o mysql8.tar
docker save redis:7-alpine -o redis.tar
docker save python:3.11-slim -o python311.tar
docker save node:18-alpine -o node18.tar
docker save nginx:alpine -o nginx.tar

# 传输到服务器
scp *.tar user@server:/tmp/

# 在服务器上加载
docker load -i /tmp/mysql8.tar
docker load -i /tmp/redis.tar
docker load -i /tmp/python311.tar
docker load -i /tmp/node18.tar
docker load -i /tmp/nginx.tar
```

> **注意**: Ctrl+C 取消拉取后，已下载的层**会自动缓存**，重新执行可从断点继续。无需手动清理。

### Q12: init_deploy.py 报 MySQL SSL/TLS 证书错误

**报错**: `ERROR 2026 (HY000): TLS/SSL error: Certificate verification failure: The certificate is NOT trusted.`
**原因**: Docker 容器内的 `python:3.11-slim` 镜像缺少 CA 证书，导致 `mysql` CLI 客户端连接 MySQL 8.0 时 TLS 验证失败。
**解决**: 本项目的 `init_deploy.py` 已改用 `asyncmy` Python 驱动连接数据库，不再调用 `mysql` CLI，此问题已修复。
> 如使用旧版 init_deploy.py 仍遇此问题，请更新到最新版本。

### Q13: aerich upgrade 超时/挂起

**原因**: 国内网络环境下 aerich 内部操作可能超时；或数据库连接配置有问题。
**解决**: 最新版 `init_deploy.py` 已内置超时回退机制 — 当 aerich upgrade 超过 60 秒未完成时，自动使用 `Tortoise.generate_schemas(safe=True)` 直接建表。
> 如需手动执行回退方案：
> ```bash
> docker exec -it aitestplatform-backend python -c "
> import sys, asyncio; sys.path.insert(0, '/app')
> from tortoise import Tortoise
> from service.core.settings import TORTOISE_ORM
> asyncio.run((lambda: __import__('asyncio').get_event_loop().run_until_complete(
>     Tortoise.init(config=TORTOISE_ORM)
> ))())
> "
> # 或直接在服务器上写脚本执行（参考 init_deploy.py 的 _fallback_generate_schemas 函数）
> ```

### Q14: Backend 启动成功但 API 请求报 TortoiseContext 错误

**报错**: `RuntimeError: No TortoiseContext is currently active. Use 'async with TortoiseContext() as ctx:' to create one, or call Tortoise.init() for global state.`
**原因**: Tortoise ORM 1.1.7+ 使用 `contextvars` 管理数据库连接状态。FastAPI 的 lifespan（启动初始化）和 HTTP 请求运行在不同的 async task 中，导致 contextvars 无法跨 task 访问。
**解决**: `service/core/database.py` 的 `init_db()` 已添加 `_enable_global_fallback=True` 参数，启用全局回退上下文：
```python
async def init_db() -> None:
    await Tortoise.init(config=TORTOISE_ORM, _enable_global_fallback=True)
```
> 修改此文件后需**重新构建** backend 镜像：
> ```bash
> docker compose -f deploy/docker-compose.yml up -d --build backend
> ```

### Q15: Backend 健康检查返回 200 但登录 API 返回 Internal Server Error

**原因**: 健康检查 `/health` 不访问数据库所以正常，但登录等 API 需要数据库访问。如果 TortoiseContext 未正确初始化（见 Q14），所有数据库操作都会失败。
**解决**: 参考 Q14 解决 TortoiseContext 问题。同时确认：
```bash
# 检查 backend 启动日志中是否有 "Application startup complete"
docker logs aitestplatform-backend 2>&1 | grep "Application startup"
# 如果有 "startup failed" 则需要检查数据库连接和表是否存在
```
