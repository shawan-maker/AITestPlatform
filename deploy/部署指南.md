## 1. 环境要求

### 方式一（Nginx 手动部署）需要的组件

| 组件 | 最低版本 | 说明 |
|------|---------|------|
| Python | 3.10+ | 推荐 3.11 |
| Node.js | 18+ | 前端构建 |
| MySQL | 8.0+ | 数据库 |
| Redis | 6+ | Token 黑名单（可选） |
| Nginx | 1.20+ | 反向代理 + 静态文件 |
| RAG Server | - | 知识库服务（独立部署） |

### 方式二（Docker Compose 部署）需要的组件

| 组件 | 最低版本 | 说明 |
|------|---------|------|
| Docker | 20.10+ | 容器引擎 |
| Docker Compose | 2.0+ | 多容器编排（compose plugin） |
| Git | 任意 | 获取代码 |

> Docker Compose 方式下，Python/Node/MySQL/Redis/Nginx 全部运行在容器内，宿主机无需安装。

## 3. 方式一: Nginx 手动部署

### 3.1 后端部署

```bash
# 1. 克隆代码
cd /opt
git clone <repo-url> aitestplatform
cd aitestplatform

# 2. 创建虚拟环境
python3.11 -m venv venv
source venv/bin/activate

# 3. 安装依赖
pip install -r requirements-service.txt

# 4. 配置环境变量
cp .env.example .env
vim .env
# 必须修改的配置:
#   DATABASE_URL       - MySQL 连接地址
#   REDIS_URL          - Redis 连接地址（可选）
#   JWT_SECRET_KEY     - 替换为随机字符串！
#   RAG_SERVER_URL     - RAG 服务地址
#   BACKEND_HOST       - 保持 127.0.0.1（仅 Nginx 可达）
#   CORS_ORIGINS       - 留空（同域部署无需 CORS）
#   LOG_FILE           - logs/backend.log

# 5. 初始化数据库（全新部署）
python deploy/scripts/init_deploy.py
# 或从旧实例迁移数据：
# 1. 在旧服务器: python deploy/scripts/export_data.py --output backup.sql
# 2. 拷贝 backup.sql 到新服务器
# 3. python deploy/scripts/init_deploy.py
# 4. python deploy/scripts/import_data.py --input backup.sql

# 6. 启动后端（推荐使用 systemd 管理）
python main.py
# 或使用 uvicorn 直接启动:
uvicorn main:app --host 127.0.0.1 --port 8000 --workers 4
```

### 3.2 前端构建

```bash
cd frontend

# 安装依赖
npm install

# 构建生产版本（自动读取 .env.production）
npm run build

# 构建产物在 frontend/dist/ 目录
ls dist/
# index.html  assets/  ...
```

### 3.3 Nginx 配置

```bash
# 1. 复制 Nginx 配置
sudo cp deploy/nginx.conf /etc/nginx/conf.d/aitestplatform.conf

# 2. 编辑配置（修改关键项）
sudo vim /etc/nginx/conf.d/aitestplatform.conf

# 必须修改:
#   server_name  → 实际域名（如 test.example.com）
#   root         → 前端 dist 目录的绝对路径（如 /opt/aitestplatform/frontend/dist）

# 3. 测试配置
sudo nginx -t

# 4. 重载 Nginx
sudo nginx -s reload
```

### 3.4 Systemd 服务管理（推荐）

创建后端服务文件 `/etc/systemd/system/aitestplatform.service`:

```ini
[Unit]
Description=AITestPlatform Backend
After=network.target mysql.service

[Service]
Type=simple
User=www-data
WorkingDirectory=/opt/aitestplatform
Environment=PATH=/opt/aitestplatform/venv/bin:/usr/bin
ExecStart=/opt/aitestplatform/venv/bin/uvicorn main:app --host 127.0.0.1 --port 8000 --workers 4
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
# 启用并启动服务
sudo systemctl daemon-reload
sudo systemctl enable aitestplatform
sudo systemctl start aitestplatform

# 查看状态
sudo systemctl status aitestplatform

# 查看日志
sudo journalctl -u aitestplatform -f
```

## 4. 方式二: Docker Compose 全家桶部署（CentOS 7 从零部署）

> 推荐方式。MySQL + Redis + 后端 + 前端全部容器化，宿主机只需安装 Docker 和 Git。
> 以下以 **CentOS 7** 为例，从空白服务器到前端页面可正常访问（含数据）。

### 4.1 安装前置依赖

#### 4.1.1 安装 Git

```bash
# 检查是否已安装
git --version

# 安装（如未安装）
sudo yum install -y git
```

#### 4.1.2 安装 Docker

CentOS 7 官方 yum 源中的 Docker 版本过旧，需使用 Docker 官方源：

```bash
# 1. 卸载旧版本（如有）
sudo yum remove -y docker docker-client docker-client-latest \
    docker-common docker-latest docker-latest-logrotate \
    docker-logrotate docker-engine 2>/dev/null

# 2. 安装依赖工具
sudo yum install -y yum-utils device-mapper-persistent-data lvm2

# 3. 添加 Docker 官方 yum 源
#    国内服务器推荐使用阿里云镜像源（速度快）：
sudo yum-config-manager --add-repo https://mirrors.aliyun.com/docker-ce/linux/centos/docker-ce.repo
#    海外服务器使用官方源：
#    sudo yum-config-manager --add-repo https://download.docker.com/linux/centos/docker-ce.repo

# 4. 安装 Docker Engine + CLI + containerd + Compose 插件
sudo yum install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin

# 5. 启动 Docker 并设置开机自启
sudo systemctl start docker
sudo systemctl enable docker

# 6. 验证安装
docker --version          # 需要 20.10+
docker compose version    # 需要 2.0+（注意是 "docker compose" 不是 "docker-compose"）
```

> **非 root 用户运行 Docker（可选）：**
> ```bash
> sudo usermod -aG docker $USER
> # 需要重新登录 shell 才能生效
> ```

#### 4.1.3 配置 Docker 镜像加速（国内服务器推荐）

国内服务器拉取 Docker Hub 镜像可能较慢，配置镜像加速器：

```bash
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json << 'EOF'
{
  "registry-mirrors": [
    "https://mirror.ccs.tencentyun.com",
    "https://docker.mirrors.ustc.edu.cn"
  ]
}
EOF

# 重启 Docker 使配置生效
sudo systemctl daemon-reload
sudo systemctl restart docker
```

### 4.2 获取代码

```bash
# 方式 A: Git 克隆（推荐，后续更新方便）
cd /opt
sudo git clone <repo-url> aitestplatform
sudo chown -R $USER:$USER aitestplatform
cd aitestplatform

# 方式 B: 从本地传输（如无 Git 仓库访问权限）
# 在本地开发机：
#   bash deploy/scripts/pack_for_server.sh
#   scp deploy/aitestplatform_deploy_*.tar.gz user@server:/opt/
# 在服务器：
#   cd /opt
#   mkdir -p aitestplatform
#   tar xzf aitestplatform_deploy_*.tar.gz -C aitestplatform
#   cd aitestplatform
```

### 4.3 配置环境变量

```bash
# 使用 Docker 专用模板
cp .env.docker .env
vim .env
```

**必须修改的配置项：**

| 变量 | 说明 | 示例 |
|------|------|------|
| `MYSQL_ROOT_PASSWORD` | MySQL root 密码，改为你自己的强密码 | `MyStr0ngP@ss2026` |
| `HTTP_PORT` | 前端 HTTP 端口（如 80 被占用则改） | `80` 或 `8080` |
| `LLM_BINDING_API_KEY` | 大模型 API Key | `sk-xxxx` |
| `EMBEDDING_BINDING_API_KEY` | 向量模型 API Key | `sk-xxxx` |
| `JWT_SECRET_KEY` | JWT 签名密钥（必须随机生成） | 见下方命令 |
| `RAG_SERVER_URL` | RAG 知识库服务地址 | `http://10.0.0.5:9621` |

```bash
# 生成安全的 JWT_SECRET_KEY
# 方式 1: 使用 openssl（CentOS 7 自带）
openssl rand -hex 32

# 方式 2: 使用 python3（如已安装）
python3 -c "import secrets; print(secrets.token_hex(32))"
```

> **注意：** Docker Compose 部署时，`DATABASE_URL` 和 `REDIS_URL` 由 `docker-compose.yml` 自动构建（使用容器内部网络地址 `mysql:3306` 和 `redis:6379`），无需在 `.env` 中手动指定。

### 4.4 配置防火墙

```bash
# 检查防火墙状态
sudo firewall-cmd --state

# 如果防火墙运行中，开放前端 HTTP 端口
sudo firewall-cmd --permanent --add-port=80/tcp       # 或你设置的 HTTP_PORT
sudo firewall-cmd --reload

# 验证
sudo firewall-cmd --list-ports
```

> 如使用云服务器（阿里云/腾讯云/华为云等），还需在 **安全组** 中放行对应端口（80 或自定义 HTTP_PORT）。

### 4.5 构建与启动

```bash
# 构建并启动所有服务（MySQL + Redis + Backend + Frontend）
# 首次构建会拉取基础镜像 + 安装依赖，耗时约 5-15 分钟
docker compose -f deploy/docker-compose.yml up -d --build

# 查看启动状态（等待所有容器变为 healthy）
docker compose -f deploy/docker-compose.yml ps
# 预期输出 4 个容器，状态均为 running/healthy:
#   aitestplatform-mysql      running (healthy)
#   aitestplatform-redis      running (healthy)
#   aitestplatform-backend    running (healthy)
#   aitestplatform-frontend   running

# 查看启动日志（首次启动建议观察，确认无报错）
docker compose -f deploy/docker-compose.yml logs -f
# Ctrl+C 退出日志查看（服务继续运行）
```

> **构建失败排查：**
> - `npm ci` 失败 → 网络问题，检查 Docker 镜像加速配置
> - `pip install` 失败 → 在 `deploy/Dockerfile.backend` 的 `pip install` 后添加 `-i https://pypi.tuna.tsinghua.edu.cn/simple`
> - `apt-get` 失败 → Debian 官方源不可达，在 Dockerfile.backend 头部添加阿里云 Debian 源

### 4.6 初始化数据库

根据部署场景选择 **4.6A（全新部署）** 或 **4.6B（从旧实例迁移数据）**。

#### 4.6A 全新部署（空库）

```bash
# 等待 MySQL 健康（首次启动约 30 秒）
docker compose -f deploy/docker-compose.yml ps | grep mysql
# 确认 mysql 状态为 healthy

# 在容器内执行数据库初始化
docker exec -it aitestplatform-backend python deploy/scripts/init_deploy.py

# 该脚本自动完成：
#   1. 检查 .env 配置
#   2. 连接 MySQL（容器内部网络，host=mysql）
#   3. 创建数据库 aiTestPlatform（如不存在）
#   4. Aerich init-db + upgrade（创建全部 38 张表）
#   5. 验证表结构
```

初始化完成后，重启后端容器以触发默认管理员创建：

```bash
docker compose -f deploy/docker-compose.yml restart backend

# 等待约 10 秒
sleep 10

# 验证后端已启动
curl -s http://127.0.0.1:8000/health
# 预期返回: {"status":"ok"} 或类似响应

# 默认管理员账号已自动创建: admin / 123456
```

#### 4.6B 从旧实例迁移数据

```bash
# ===== 在旧服务器（开发机）导出数据 =====
cd D:/PyProject/AITestPlatform
# 如果已有备份文件可跳过此步
PYTHONPATH=. python deploy/scripts/export_data.py --output deploy/backup_20260712.json

# 将备份文件传输到新服务器
scp deploy/backup_*.json user@server:/opt/aitestplatform/

# ===== 在新服务器操作 =====

# 1. 先初始化空库（建表）
docker exec -it aitestplatform-backend python deploy/scripts/init_deploy.py

# 2. 将备份文件复制到后端容器内
docker cp backup_20260712.json aitestplatform-backend:/app/deploy/

# 3. 执行数据导入（自动按 FK 依赖顺序导入 42 张表，跳过冲突记录）
docker exec -it aitestplatform-backend \
    python deploy/scripts/import_data.py \
    --input deploy/backup_20260712.json \
    --on-conflict=skip

# 4. 或使用一键迁移脚本（含自动验证，自动对比源库/目标库行数）
docker exec -it aitestplatform-backend \
    python deploy/scripts/migrate_to_server.py \
    --backup deploy/backup_20260712.json
```

### 4.8 常用运维命令

```bash
# 重启单个服务
docker compose -f deploy/docker-compose.yml restart backend

# 重新构建前端（前端代码更新后）
docker compose -f deploy/docker-compose.yml build frontend
docker compose -f deploy/docker-compose.yml up -d frontend

# 更新代码后重新部署（保留数据）
cd /opt/aitestplatform
git pull
docker compose -f deploy/docker-compose.yml up -d --build

# 进入后端容器排查问题
docker exec -it aitestplatform-backend bash

# 查看后端日志（最近 100 行 + 持续输出）
docker logs -f aitestplatform-backend --tail 100

# 查看 MySQL 日志
docker logs -f aitestplatform-mysql --tail 50

# 停止所有服务（数据保留在 volume 中，不会丢失）
docker compose -f deploy/docker-compose.yml down

# 停止并清除所有数据（危险！会删除数据库和所有文件）
docker compose -f deploy/docker-compose.yml down -v

# 数据库 schema 迁移（代码更新后如有新表/字段）
docker exec -it aitestplatform-backend python deploy/scripts/db_manage.py upgrade

# 数据库备份（导出到容器内，再复制到宿主机）
docker exec -it aitestplatform-backend \
    python deploy/scripts/export_data.py --output /app/data/backup.sql
docker cp aitestplatform-backend:/app/data/backup.sql ./backup.sql
```

### 4.9 Docker Volume 说明

| Volume | 容器 | 内容 |
|--------|------|------|
| `mysql-data` | mysql | MySQL 数据库文件 |
| `redis-data` | redis | Redis 持久化数据 |
| `app-data` | backend | 知识库文件、测试文件等运行时数据 |

> 执行 `docker compose down` 不会丢失数据，volume 默认保留。
> 执行 `docker compose down -v` 会删除所有 volume（慎用）。

## 5. 数据库部署与迁移

### 5.1 场景说明

| 场景 | 命令 |
|------|------|
| **全新部署**（空库） | `python deploy/scripts/init_deploy.py` |
| **从旧实例迁移数据** | 旧库导出 → 新库导入 |
| **仅升级 schema**（数据不动） | `python deploy/scripts/db_manage.py upgrade` |

### 5.2 全新部署

```bash
# 1. 检查配置（不执行）
python deploy/scripts/init_deploy.py --dry-run

# 2. 执行初始化（建库 → 建表 → 应用迁移 → 验证）
python deploy/scripts/init_deploy.py

# 3. 启动后端（自动创建默认管理员 admin/123456）
python main.py
```

`init_deploy.py` 会自动完成：
- 检查 `.env` 配置是否完整
- 连接 MySQL 并创建数据库（如不存在）
- 运行 Aerich init-db + upgrade（创建全部 38 张表）
- 验证表结构

### 5.3 从旧实例迁移数据

#### 方案 A: mysqldump（推荐，最快速完整）

```bash
# === 旧服务器 ===
python deploy/scripts/export_data.py --output backup_20260708.sql

# 仅导出表结构（不含数据）：
# python deploy/scripts/export_data.py --output schema_only.sql --no-data

# === 传输到新服务器 ===
scp backup_20260708.sql user@newserver:/opt/aitestplatform/

# === 新服务器 ===
# 先初始化空库
python deploy/scripts/init_deploy.py
# 再导入数据
python deploy/scripts/import_data.py --input backup_20260708.sql
```

#### 方案 B: JSON 格式（跨数据库兼容，无需 mysqldump）

```bash
# === 旧服务器 ===
python deploy/scripts/export_data.py --output backup.json

# === 新服务器 ===
python deploy/scripts/init_deploy.py
python deploy/scripts/import_data.py --input backup.json --on-conflict=skip
```

JSON 导入的冲突处理策略：
- `--on-conflict=skip` — 跳过已存在的记录（默认）
- `--on-conflict=update` — 覆盖更新已存在的记录
- `--on-conflict=error` — 遇到冲突立即报错

### 5.4 脚本工具一览

| 脚本 | 用途 |
|------|------|
| `deploy/scripts/init_deploy.py` | 全新部署初始化（建库+建表+验证） |
| `deploy/scripts/export_data.py` | 导出数据（.sql 或 .json） |
| `deploy/scripts/import_data.py` | 导入数据（.sql 或 .json） |
| `deploy/scripts/migrate_to_server.py` | 服务器一键迁移（建库+建表+导数据+验证） |
| `deploy/scripts/pack_for_server.sh` | 本地打包（代码+备份+配置→tar.gz） |
| `deploy/scripts/db_manage.py` | Aerich 迁移管理（migrate/upgrade/downgrade） |
| `deploy/scripts/tools/diag_rag.py` | RAG 知识库诊断 |
| `deploy/scripts/tools/update_i18n.py` | i18n 翻译批量更新 |

## 6. 配置说明

### 6.1 环境变量一览（.env）

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `BACKEND_HOST` | `127.0.0.1` | 后端监听地址。Docker 中自动覆盖为 `0.0.0.0` |
| `BACKEND_PORT` | `8000` | 后端端口 |
| `CORS_ORIGINS` | *(空)* | CORS 允许的前端域名，逗号分隔。**同域 Nginx 部署留空** |
| `LOG_FILE` | *(空)* | 日志文件路径。留空仅输出到控制台 |
| `JWT_SECRET_KEY` | `change-me-in-production` | **⚠️ 必须修改！** 用于 JWT 签名 |
| `DATABASE_URL` | - | MySQL 连接串（Docker 部署由 compose 自动构建） |
| `REDIS_URL` | - | Redis 连接串（Docker 部署由 compose 自动构建，可选） |
| `RAG_SERVER_URL` | `http://127.0.0.1:9621` | RAG 知识库服务地址 |

### 6.2 前端环境变量（frontend/.env.production）

| 变量 | 生产值 | 说明 |
|------|--------|------|
| `VITE_API_BASE_URL` | `/api/v1` | API 请求路径，走 Nginx 代理 |
| `VITE_BACKEND_ORIGIN` | *(空)* | SSE 请求地址。**同域 Nginx 部署务必留空** |

### 6.3 Nginx 关键配置说明

| 配置项 | 作用 |
|--------|------|
| `proxy_buffering off` | SSE 流式推送必须关闭缓冲 |
| `proxy_read_timeout 700s` | AI 智能体生成超时（Agent 默认 600s） |
| `try_files $uri $uri/ /index.html` | Vue Router History 模式路由回退 |
| `client_max_body_size 20m` | 文件上传大小限制 |
| `gzip on` | 静态资源压缩传输 |

## 7. 常见问题排查

### Q1: 刷新页面 404
**原因**: Vue Router History 模式需要 Nginx 回退到 `index.html`
**解决**: 确认 Nginx 配置中有 `try_files $uri $uri/ /index.html;`

### Q2: AI 智能体生成无响应 / 卡住
**原因**: Nginx 缓冲了 SSE 流式响应
**解决**: 确认 `/api/v1/ai-generation/` 的 location 块中有 `proxy_buffering off;`

### Q3: API 请求 CORS 报错
**原因**: 同域部署不需要 CORS，但后端仍配置了 CORS origins
**解决**: `.env` 中 `CORS_ORIGINS` 留空即可

### Q4: SSE 连接超时断开
**原因**: Nginx 的 `proxy_read_timeout` 太短
**解决**: 确保设为 700s 以上（大于 Agent 超时 600s）

### Q5: 文件上传失败 (413)
**原因**: Nginx 默认 `client_max_body_size` 为 1MB
**解决**: 在 Nginx 配置中设置 `client_max_body_size 20m;`

### Q6: 后端启动报 JWT 密钥警告
**原因**: 使用了默认的 `change-me-in-production`
**解决**: 在 `.env` 中设置安全的 `JWT_SECRET_KEY`（建议 32 位随机字符串）

### Q7: 健康检查失败
**排查**:
```bash
# 直接请求后端
curl http://127.0.0.1:8000/health

# 通过 Nginx/Docker 请求
curl http://your-domain.com/health

# Docker 部署：检查后端容器日志
docker logs aitestplatform-backend --tail 50
```

### Q8: Docker 构建时 pip/npm 超时
**原因**: 国内服务器访问境外源慢
**解决**:
```bash
# pip: 在 deploy/Dockerfile.backend 的 pip install 后追加:
RUN pip install --no-cache-dir -i https://pypi.tuna.tsinghua.edu.cn/simple -r requirements-service.txt

# npm: 在 deploy/Dockerfile.frontend 的 npm ci 前添加:
RUN npm config set registry https://registry.npmmirror.com
```

### Q9: Docker 容器启动后 backend 反复重启
**排查**:
```bash
# 查看容器退出原因
docker inspect aitestplatform-backend --format='{{.State.ExitCode}} {{.State.Error}}'

# 查看容器日志（含启动报错）
docker logs aitestplatform-backend --tail 100

# 常见原因：
# - DATABASE_URL 连接失败 → 检查 MySQL 容器是否 healthy
# - 缺少必需的环境变量 → 检查 .env 是否完整
```
